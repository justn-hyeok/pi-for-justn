# p4j Naming

p4j uses functional names over lore names. A name should explain what the role or mode does without requiring project-specific mythology.

## CLI

- `p4j`: personal Pi wrapper for Justn.
- `pi`: upstream-compatible escape path through `p4j pi ...`.

## Workflow Modes

- `quick`: small bounded work.
- `think`: analysis before action.
- `search`: bounded local-first search.
- `plan`: plan-first workflow.
- `build`: implementation-focused work.
- `review`: verification and critique.
- `ship`: release/checklist planning.
- `local`: safe local diagnostics planning.
- `team`: lightweight team-mode planning.
- `ulw`: finish end-to-end while staying lean.

## Roles

- `lead`: orchestration and scope control.
- `planner`: planning and acceptance criteria.
- `builder`: implementation.
- `researcher`: external docs and GitHub research.
- `scout`: local codebase search.
- `reviewer`: review and verification.
- `local`: local system operations.
- `release`: git, CI, tags, releases, smoke-test planning.
- `designer`: UI/UX work.
- `debugger`: hard bugs and architecture tradeoffs.
